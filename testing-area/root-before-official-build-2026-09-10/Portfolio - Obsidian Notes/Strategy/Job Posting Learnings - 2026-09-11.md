## Main Portfolio Implication

The portfolio should prove that Wesley can turn game-design needs into working, maintainable gameplay systems.

The best evidence is not just a finished screenshot or broad project description. The strongest evidence is a small, explainable system with visible gameplay effect, clear ownership, debugging/iteration notes, and enough code/process proof to support a technical conversation.

## Repeated Job-Posting Signals

Early repeated signals:

- Unity/C# appears frequently.
- Unreal Engine 5 / Blueprints appears in intern and senior/engine-side postings.
- Git or version control appears repeatedly.
- Portfolio, shipped work, completed games, code repositories, or playable builds appear repeatedly.
- Communication, self-organization, and small-team collaboration are treated as practical job skills.
- Debugging and problem-solving are expected even in junior/intern-shaped roles.
- Several roles expect programmers to translate design requirements into gameplay code, UI, or tools.

## Portfolio Content Priorities

### Highest-Value Evidence To Show

- Completed or playable work.
- Gameplay systems with clear design goals.
- UI/gameplay implementation where relevant.
- Debugging and iteration.
- Clean, maintainable C# / Unity code where possible.
- Unreal / Blueprint work as a secondary lane, especially when the case study can explain implementation decisions.
- Git/source-control process, even if shown through concise narrative rather than public commit history.
- Collaboration with designers/artists/non-technical teammates.

### Case Study Questions To Emphasize

These should influence project pages and dossiers:

- What design requirement or player-facing problem was I solving?
- What system did I build?
- How did I structure it?
- What tradeoffs did I make?
- What broke or changed during implementation?
- How did I debug or iterate?
- What would I improve next?
- What evidence can a reviewer inspect: build, clip, diagram, code excerpt, repo, or screenshot?

This reinforces [[Kevin Nappoly]]'s portfolio advice from the Austin Unreal meetup: show the goal, priorities, ending state, failure/learning, and project-shaping decisions.

## Project Selection Implications

### Spa Game / Alien Spa

This remains the strongest flagship candidate because it maps directly to repeated posting signals:

- Unity/C#.
- Gameplay/simulation systems.
- Design requirements becoming working systems.
- Small-team collaboration.
- UI/planning-to-runtime loop potential.
- Systems that can be explained as architecture rather than isolated scripts.

New emphasis: make the case study visibly about translating design/player needs into maintainable gameplay systems. Evidence should include a focused clip or diagram showing the planning-to-simulation loop, guest needs/action selection, and resource/item workflows.

### Tides of Eternity

This remains a strong supporting systems case study if public-use permission is resolved.

New emphasis: position it as external-GDD-to-code translation, combat systems architecture, debugging/iteration, and status-effect design. It is valuable because postings repeatedly reward the ability to turn design requirements into gameplay systems.

### Demons and Dining Darling

This remains important because it fills the completed/public-proof gap.

New emphasis: show that Wesley can deliver a playable loop in a team setting under constraints. The strongest proof is not deep architecture but complete implementation, integration, and visible game flow.

### Future Projects

Future project choices should be shaped by gaps from real postings, not panic from senior listings.

Good future project criteria:

- Small enough to finish and polish.
- Has one or two clear gameplay systems.
- Has visible UI or player-facing interaction.
- Can produce a playable build, short clip, and code excerpt.
- Demonstrates debugging/iteration or performance awareness.
- Adds a distinct competency not already covered by Spa/Tides/Demons.

Avoid starting large new projects just to chase every keyword.

## Skill Gap Implications

New or reinforced gaps from postings:

- Debugging proof.
- Git/source-control process proof.
- Portfolio/code repository visibility.
- Completed-game or finished-demo evidence.
- UI implementation evidence.
- Optimization/profiling evidence, especially for more advanced roles.
- Data-oriented/runtime-allocation awareness for deeper Unity gameplay roles.
- Unreal/C++ depth is a later layer; Unreal/Blueprints can still matter for intern/junior-shaped opportunities.

## Strategic Conclusion

The most likely near-term positioning is:

**Unity/C# gameplay generalist with visible systems work, plus Unreal/Blueprints as a secondary lane.**

The portfolio should help a small studio imagine assigning Wesley a contained gameplay/UI/system task and trusting him to implement it, communicate clearly, debug it, and finish it.
