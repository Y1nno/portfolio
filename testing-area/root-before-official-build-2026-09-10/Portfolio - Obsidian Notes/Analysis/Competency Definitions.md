# Competency Definitions

Use these definitions when evaluating projects in [[Competency Matrix]]. A project should not receive credit for a competency merely because a technology name appears in the project description.

These definitions should be interpreted through [[Portfolio Evaluation Framework]], especially the rule that project value depends on what the project proves.

## Evaluation Scale

| Level | Meaning |
| --- | --- |
| 0 | No evidence yet. |
| 1 | Superficial exposure; used or touched but no clear ownership or reasoning. |
| 2 | Basic implementation; personally contributed but limited complexity or evidence. |
| 3 | Credible capability; personally implemented meaningful work with evidence and explanation. |
| 4 | Strong evidence; solved nontrivial problems, made tradeoffs, and can discuss architecture/debugging. |
| 5 | Flagship evidence; demonstrates standout capability suitable for deep interview discussion. |

## Initial Competencies

| Competency | Credible Evidence Requires |
| --- | --- |
| Gameplay systems | Personally implemented mechanics, controls, state, physics interaction, responsiveness, edge cases, tuning, or feature iteration with clear behavior, constraints, and integration details. |
| C# | Code samples or implementation evidence showing competent use beyond basic syntax. |
| C++ | Confirmed project work, code, or systems using C++. |
| Python | Confirmed project work, tooling, automation, or scripts using Python. |
| Engine knowledge | Evidence of using engine systems deliberately, including workflows, lifecycle, scene/content structure, physics, rendering, input, tooling, profiling, or build constraints; not merely building inside an engine. |
| Object-oriented design | Clear ownership boundaries, interfaces, composition, inheritance decisions, or dependency management. |
| Architecture | System boundaries, data flow, event flow, modularity, or scaling decisions with tradeoffs. |
| Algorithms/data structures | Specific algorithmic choices or data structures used to solve a real project problem. |
| AI systems | Behavior logic, navigation, decision-making, perception, pathfinding, state machines, behavior trees, utility AI, debugging visualization, tuning, or performance considerations. |
| Tools | Editor tools, pipelines, validation, error handling, debug utilities, automation, CI/build support, content-authoring support, or workflow improvements for developers/designers. |
| Debugging | Specific difficult bugs, investigation methods, instrumentation, and resolution. |
| Optimization | Profiling, bottleneck identification, performance changes, or memory/runtime tradeoffs. |
| Collaboration | Team process, code review, handoffs, documentation, conflict resolution, or interdisciplinary work. |
| Source control | Meaningful Git workflow, branching, PRs, issue tracking, history evidence, collaboration, or commits that corroborate contribution while recognizing commit history is not unquestionable proof. |
| Iteration | Evidence of changing approach based on testing, feedback, constraints, or failures. |
| Technical communication | Docs, diagrams, explanations, planning artifacts, or clear case-study reasoning. |
| Polish/completion | Finished builds, user-facing polish, bug fixing, deployment, or shipped milestones. |

## Notes

## Role-Dependent Weighting

Different target roles weight competencies differently:

| Role Family | Higher-Weight Competencies |
| --- | --- |
| Gameplay programming | Gameplay systems, engine knowledge, iteration, debugging, collaboration, polish/completion, C# or C++ depending on engine. |
| Systems / engine programming | C++, architecture, engine knowledge, optimization, debugging, algorithms/data structures, source control. |
| Tools programming | Tools, Python and/or C++, validation, automation, documentation, debugging, technical communication, source control. |
| AI programming | AI systems, algorithms/data structures, debugging, engine knowledge, architecture, optimization. |
| Generalist game programming | Breadth across gameplay, tools, systems, debugging, UI/AI where relevant, plus at least one area of clear depth. |

These categories may evolve after [[Personal Positioning]] clarifies target roles and after actual job postings are reviewed.
