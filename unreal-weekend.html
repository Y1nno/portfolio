Mario World 1-1 in Unreal

Gameplay implementation

I built a third-person platformer inspired by Super Mario Bros. World 1-1 during Indie Game Academy's Unreal workshop. Within that weekend, I learned a new engine and a visual approach to programming while building a complete playable experience, from the main menu through platforming, death and restart, and a finish. I published the packaged Windows build the day after the workshop weekend ended.

Instruction covered creating game objects, collisions, and basic Blueprint construction. Beyond those fundamentals, the project was largely self-directed: I implemented the gameplay, integrated imported assets, and worked through packaging.

What I built

  • Assembled a third-person course with pipes, blocks, gaps, stairs, and a flagpole finish.
  • Built actor Blueprints for the player, Goombas, coin/question blocks, and flagpole, and integrated an imported character model and animations into the third-person setup.
  • Implemented enemy behavior, question-block and coin interactions, and HUD feedback.
  • Connected the main menu, death and restart behavior, and flagpole-triggered win flow.
  • Integrated models, materials, UI assets, and audio, then packaged and shared the Windows release.

What I took from it

Working with Blueprints came with a trade-off. The visual connections made gameplay logic feel more approachable than written code, but they changed how I approached a behavior. In C#, I often started with the variables and data I had, then worked forward through transformations toward the result. In Blueprints, I found myself starting with the action I wanted and working backward through its inputs to the source data.

That took some adjustment, especially while I was still learning which actions Unreal made available. I relied on familiar fundamentals to find a starting point. For controlled actor movement, for example, I knew I could use a value that changed over time to apply small changes to the actor's position over a set duration. That gave me a concrete behavior to work toward while I learned how to express it in Blueprints.

I'm proud of how quickly I adapted to both a new engine and a different way of constructing logic, and that I brought the pieces together into a complete experience within the weekend. The tight deadline gave the work a game-jam rhythm: learning, making scope decisions, and getting the full gameplay loop working together. Seeing my game development fundamentals carry over from other projects and learning experiences helped me finish while the tools were still unfamiliar.

Finishing this project gave me confidence to take on more complex Unreal projects. I look forward to opportunities to build on that foundation and expand my Unreal skills.
