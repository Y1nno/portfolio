# Portfolio Research Questions

This note defined what the Portfolio Researcher should investigate. The findings from `C:\Users\wesle\Downloads\Portfolio Evaluation Framework.pdf` have been incorporated into [[Portfolio Evaluation Framework]] and summarized in [[Research Source Register]].

## Recruiter Skim

- What does a recruiter need to understand in 10-30 seconds?
- What role signal should appear on the homepage?
- What information must be immediately visible: role, location/availability, tools, resume, contact, project highlights?
- What makes a game programming portfolio confusing to skim?

## Technical Hiring Review

- What do technical hiring managers inspect in programmer portfolios?
- How much technical depth is useful before it becomes noise?
- What makes a code sample credible?
- What diagrams, clips, or explanations help validate systems knowledge?
- How should tradeoffs, failed approaches, and debugging be presented?

## Game Programmer Portfolio Standards

- How does a programming portfolio differ from an art, design, or generalist game portfolio?
- What competencies should it demonstrate for gameplay, tools, systems, engine, and technical design roles?
- How should unfinished or prototype projects be handled?
- How should collaborative work be attributed?

## Project Inclusion Criteria

- What makes a project worth featuring?
- What makes a project better suited as a secondary mention?
- When should a project be omitted even if it exists?
- How many projects should receive deep case studies?

## Evidence and Assets

- What asset types are persuasive for programming work?
- When are screenshots enough?
- When are GIFs, videos, diagrams, profiler captures, or code excerpts needed?
- How should GitHub links support, not replace, explanation?

## Common Failures

- What common portfolio failures should this vault prevent?
- What examples exist of vague claims, overdesigned pages, weak attribution, or excessive code dumps?

## Research Output Requirements

The final research output should update [[Portfolio Evaluation Framework]] with:

- evaluation categories;
- specific criteria;
- examples of strong and weak evidence;
- source links or citations where appropriate;
- unanswered assumptions marked as NEEDS RESEARCH.
