Tides of Eternity

(Role: Gameplay Programmer)

Tides of Eternity is an in-development Unity/C# roguelite combat prototype built by a rev-share team. I joined after the project already had an external game design document, then began translating its combat direction into playable prototype systems.

My strongest contribution is a runtime status-effect architecture that supports data-configured modifiers, stacking, ticking, expiration, and interactions such as Chill converting into Freeze.

What I contributed

  • Implemented isometric movement and dash behavior for a Hades-style combat prototype.
  • Built a bounded damage calculation pipeline based on external GDD limits.
  • Designed a runtime status-effect system with stacks, duration, ticking, expiration, modifier aggregation, and status-specific hooks.
  • Implemented data-configured combat modifiers so movement and damage systems can consume status effects without hardcoded checks for every status.
  • Created status interactions such as Chill converting into Freeze, giving the prototype visible combat behavior while keeping the system flexible.

Code proof

The status system treats statuses as runtime instances instead of simple flags. That lets each status own behavior such as stacks, ticking, expiration, and conversion triggers while movement and damage code query shared modifier results. 

protected override void OnStackAdd(int stacks)
{
    if (Stacks == ((ChillStatusDefinition)Definition).chillToFreezeThreshold)
    {
        statusManager.ApplyStatus(StatusType.Freeze, Source);
    }
}

What I learned

Tides changed how I think about game design documents. A useful GDD needs subjective direction, but implementation also needs concrete answers: triggers, values, stack rules, timing, ownership, and edge cases.

The status architecture was my response to that ambiguity: build a flexible foundation that supports the current prototype while leaving room for the design to evolve.
