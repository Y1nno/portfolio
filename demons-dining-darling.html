Demons & Dining, Darling!

(Role: Unity Developer / Gameplay Programmer)

Demons & Dining, Darling! is a public cooking and dating-sim prototype built during Indie Game Academy Level 1. I was the Unity Developer / Gameplay Programmer on a mixed-discipline team, implementing the playable systems and integrating teammate-created art, writing, and game design inputs.

The prototype shipped publicly on Itch with browser and Windows builds, and the team tied for 3rd place.

What I contributed

Code proof

This excerpt shows the order system resolving a served dish, checking it against the active ticket, and applying feedback through patience, affection, and chef prompts. 

public void ResolveOrder(GameObject order)
{
    if (order != null && orders.Contains(order))
    {
        RemoveOrder(order);
        List<Ingredient> platedIngredients = platingStation.GetIngredients();
        platingStation.ClearIngredients();
        EvaluateOrder(order, platedIngredients);
    }
}

public void EvaluateOrder(GameObject order, List<Ingredient> platedIngredients)
{
    if (GetComponent<TutorialSignaler>())
    {
        GetComponent<TutorialSignaler>().Signal(LevelSignal.ResolvedFirstOrder);
    }
    if (platedIngredients.Count == 1 && platedIngredients[0].definition == order.GetComponent<Ticket>().order)
    {
        PatienceManager.Instance.IncreasePatience(orderApprovalReward);
    }
    else
    {
        AffectionManager.Instance.DecreaseAffection(orderPenalty);
        AddPrompt(servedWrongPrompt);
    }
}

Teamwork and process

This was a team jam project, not a solo project. I owned the Unity implementation and integration, while teammates contributed the art, writing, and game design direction/content.

The public postmortem credits me with recommending the team's 4 L retrospective format, which helped us reflect on scope, process, and communication after shipping the prototype.

The main portfolio value here is delivery: a complete playable loop, a public release, and a team project finished under jam constraints.

- Project focus

What I learned

  • Short jams reward implementation that connects systems quickly instead of overbuilding isolated architecture.
  • Clear attribution matters on team projects: implementation ownership, design direction, art, and writing should each be described separately.
  • A public prototype can be valuable portfolio evidence when paired with honest scope, visible gameplay, and a specific code proof.
